# CoreYard v0.1.0 evidence ledger

One row per acceptance criterion, as QA-02 requires. `scripts/ledger.py` fails if a
criterion in [the specification](../RELEASE_ACCEPTANCE_v0.1.0.md) has no row here, or if a
row names a criterion the specification no longer defines.

**Missing evidence is NOT VERIFIED, never PASS** (REL-04). Most rows below are NOT
VERIFIED, and that is the honest state of the release rather than an oversight: the offline
suite passing is development evidence, and does not establish clean customer installation,
live integration behaviour, recovery, capacity or the soak gates.

A status here is a claim about *this* commit. Any later artifact or code change invalidates
the affected rows and requires re-verification (QA-03).

| Status | Meaning |
|---|---|
| PASS | Evidence collected at this commit and reviewed. |
| IN PROGRESS | Work landed and referenced, but the criterion is not yet fully met. |
| NOT VERIFIED | No evidence collected. The default, and not a judgement that it fails. |
| FAIL | Evidence collected and the criterion is not met. |
| N/A | Outside the scope of this release by an explicit, dated decision. Requires a reason. |

## What each row is waiting on

The **Needs** column exists because "42 criteria unverified" is not a plan. Most of what is
left is not blocked on judgement or on writing more code — it is blocked on an environment
that does not exist yet, and those are different problems with different owners.

| Needs | Meaning |
|---|---|
| `offline` | Provable in this repository with synthetic fixtures. No external service, no yard. |
| `test store` | A Shopify development store, published to and inspected. |
| `disposable database` | A mapped SQL Server that may be written to and thrown away. `ORD-02` says so in as many words: SQL-string unit tests do not establish transaction safety. |
| `live yard` | The maintaining installation, or another real one. |
| `spare host` | A machine to restore onto, upgrade and roll back. |
| `capacity host` | 4 cores / 8 GiB, loaded to the `PERF-01` reference dataset. |
| `soak host` | A controlled installation left running for 14 days (`QUAL-01`). |
| `two testers` | Two people who have not seen the code, working from public documentation only. |
| `release owner` | A named person. Several criteria are a sign-off, not a test. |
| `release act` | Happens at or after tagging: artifacts, checksums, provenance. |

Owner and environment are unassigned until a release owner is named (SEC-04, QA-03).
